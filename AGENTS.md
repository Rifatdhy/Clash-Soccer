# Clash.Soccer — Agent Guide

Website komunitas mini soccer: jadwal pertandingan, RSVP, berita, galeri, FAQ. Next.js 16 App Router + React 19 + PostgreSQL.

## Commands

```bash
# Development
npm run dev                       # dev server http://localhost:3000
npm run build                     # production build (does NOT need a database)
npm run lint
npx tsc --noEmit                  # type check

# Tests
npm test                          # unit tests (node --test), no DB needed
npm run test:integration          # requires TEST_DATABASE_URL set
npm run test:e2e                  # Playwright, starts dev server automatically

# Database
npm run db:migrate                # run pending migrations (reads .env.local/.env)
npm run db:migrate -- --dry-run   # preview pending without applying
npm run db:migrate -- --status    # list applied versions
npm run seed:demo                 # fill with demo data
npm run seed:demo -- --reset      # wipe demo data first, then re-seed
npm run smoke:db                  # end-to-end RSVP smoke test against DB

# Utilities
npm run hash-password             # print ADMIN_PASSWORD_HASH from env ADMIN_PASSWORD
```

## Required env vars (production)

| Var | Notes |
|-----|-------|
| `DATABASE_URL` | Add `?sslmode=disable` for local Postgres without TLS |
| `ADMIN_USERNAME` | |
| `ADMIN_AUTH_SECRET` | Min 32 chars |
| `ADMIN_PASSWORD_HASH` | Preferred; generated by `npm run hash-password` |
| `ADMIN_PASSWORD` | Plaintext fallback if hash not set |
| `SITE_URL` | Full https URL, used by sitemap/robots/JSON-LD |

Dev defaults exist for `DATABASE_URL` (`localhost:5432/clash_soccer`) and `ADMIN_AUTH_SECRET`. Build skips DB entirely (`NEXT_PHASE=phase-production-build`).

## Architecture

```
src/
  app/           # Next.js App Router — pages + API routes
    api/         # Route handlers (matches, rsvps, news, albums, faqs, settings, uploads, auth, health)
    admin/       # Admin pages (login, dashboard, matches, news, gallery, rsvp, settings)
  lib/           # Server and shared logic (no page files)
  components/    # React components
  types/index.ts # All shared TypeScript types
migrations/      # Sequential SQL files: NNNN_name.sql
scripts/         # Node .mjs scripts (migrate, seed, smoke, hash-password)
tests/           # Unit tests (node --test, *.test.ts)
tests/integration/ # Integration tests — need TEST_DATABASE_URL
e2e/             # Playwright tests
```

**Key module boundaries:**
- `src/lib/data.ts` — all server reads for public pages, with 30s in-memory cache
- `src/lib/data-cache.ts` — cache store on `globalThis` (shared across Next.js module graphs); call `invalidateDataCache()` after every write
- `src/lib/rsvp-service.ts` — RSVP create/delete with `FOR UPDATE` row lock + transaction
- `src/lib/rate-limit.ts` / `rate-limit-store.ts` — memory or Postgres store; falls back to memory on error
- `src/lib/storage.ts` — local or S3 driver; always serves via `/api/uploads/<key>` regardless of driver
- `src/proxy.ts` — Next.js middleware: guards `/admin`, adds CSP nonce per request, sets `x-request-id`
- `src/lib/sql.ts` — `buildUpdate()` builds parameterized UPDATE from a field whitelist (column names from code, values as params)

## Conventions

**API responses:** Always `{ success: true, data, error: null }` or `{ success: false, error: { message, details }, data: null }`. Use helpers from `src/lib/api-helpers.ts` — never return raw `NextResponse.json` directly in routes.

**Validation:** Zod schemas at the route level, run via `validate(req, schema, handler)` from `api-helpers.ts`. That helper enforces the 3 MB JSON body cap and streams counting to defeat chunked bypass.

**Logging:** Use `createLogger()` from `src/lib/logger.ts` everywhere — never `console.log/error/warn` directly in lib or routes. The logger redacts secrets and PII keys automatically.

**Auth:** `src/proxy.ts` guards `/admin/**` via JWT cookie. Route handlers also call `requireAdmin()` as a second check. `isAdminRequest()` reads the same `httpOnly` cookie — do not try to manipulate it from client JS.

**Migrations:** Add a new `migrations/NNNN_name.sql` file. Never edit existing files. The script and `/api/db-init` both use PostgreSQL advisory lock `4829163` so concurrent deploys don't collide.

**Upload keys:** Always random (`randomUUID().extension`). Storage cleanup checks DB references before deleting — call `releaseUploadsFor()` or `releaseReplacedUploads()` from `storage-cleanup-server.ts` after any delete/update that removes an image URL.

**Rate limits:** Login: 5/15 min. RSVP: 20/15 min. Both emit `Retry-After` header. Set `RATE_LIMIT_STORE=database` for multi-instance deploys.

**Path alias:** `@/*` → `src/*`.

## Testing

- Unit tests: `tests/*.test.ts`, run with `node --test` (Node 24 required). No DB.
- Integration tests: `tests/integration/*.test.ts`, need `TEST_DATABASE_URL`. Skipped automatically if unset.
- E2E: `e2e/`, Playwright Chromium only, single worker, no parallelism. Uses hardcoded test credentials from `playwright.config.ts` (`admin` / `e2e-password-123`). Dev server starts automatically; reuses existing server outside CI.

**Run a single unit test file:**
```bash
node --test tests/slots.test.ts
```

**Integration test prerequisites:**
```bash
# PowerShell
$env:TEST_DATABASE_URL="postgresql://postgres:postgres@localhost:5432/clash_soccer_test"
npm run db:migrate
npm run test:integration
```

## Known quirks

- `npm run build` must succeed without a database (`assertEnv` skips during build phase).
- `data-cache.ts` stores cache on `globalThis` — not module-level — because Next.js route handlers and pages are separate module graphs that otherwise get separate Maps.
- Cache prunes at 500 entries (hard cap 400) to prevent unbounded growth from arbitrary `?slug=` crawling.
- `src/lib/rsvp-service.ts` uses `SELECT ... FOR UPDATE` on the match row to serialize concurrent RSVP submissions — do not remove without replacing with an equivalent lock.
- The upload endpoint identifies images by their leading bytes, not `file.type`, then decodes and re-encodes them with `sharp` (`src/lib/image-normalize.ts`) so trailing payloads and embedded metadata never reach storage. Keep the upload route on the Node runtime; `sharp` does not run on Edge.
- Google Maps embed URL in settings is validated to start with `https://www.google.com/` — anything else is rejected.
